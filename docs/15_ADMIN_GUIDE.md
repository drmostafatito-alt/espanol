## 2. إنشاء حساب الإدارة الأول

```bash
npm run admin:create -- --env staging --email owner@example.com
# السكربت: يطلب كلمة مرور تفاعليًا (لا تُطبع)، يتحقق من قوتها، ينشئ المستخدم بدور super_admin،
# ويكتب ADMIN_BOOTSTRAP_DONE=true. يرفض العمل إن وُجد super_admin.
```
- لا كلمة مرور افتراضية في المستودع.
- في الإنتاج: يُفضَّل إنشاء الحساب عبر `wrangler secret`/سكربت محلي مع جهاز موثوق.

## 3. مسار نشر درس (تشغيليًا)

1. **أضف/استورد** ملف الدرس (`content/exemplars/lesson-*.json`) واربطه في `paths.json`.
2. شغّل `node tools/validate-content.mjs` → يجب 0 أخطاء.
3. ارفع عبر `/admin/lessons/import` (سيرفض الملف عند أي خطأ بنيوي).
4. الحالة `draft` → أرسل للمراجعة → يسجّل `content_review_records` لكل مرحلة.
5. بعد سجلي المراجعة (إسباني + عربي) + مطابقة الصوت → **نشر**.
6. أي تعديل جوهري ينشئ `lesson_versions` جديدة؛ النتائج التاريخية تبقى على الإصدار القديم.

## 4. سياسات إلزامية في الإدارة

| السياسة | القاعدة |
| --- | --- |
| لا حقن JS | لا حقل في الإعدادات يقبل `<script>`. الإعلانات عبر `ads_configuration` بمعرّف مزوّد معتمد فقط |
| لا أسرار معروضة | لا يمكن لأي دور رؤية كلمة مرور أو توكن — لا وجود لهما أصلًا كنص |
| كشف البيانات | صفحة المستخدم تعرض التقدم والبلاغات فقط، بلا رسائل خاصة أو تسجيلات |
| التدقيق | كل عملية حساسة (نشر، تعديل إعداد، تعليق حساب، تصدير) تُسجل في `admin_audit_logs` |
| التصدير | CSV/JSON للتحليلات بلا بريد ولا معرّفات شخصية (مستخدم مُجهَّل) |
| حذف أصل | يُمنع إن كان مستخدمًا في محتوى منشور؛ يُعرض «أين يُستخدم» أولًا |

## 5. مهام صيانة دورية

| الدور | المهمة | التواتر |
| --- | --- | --- |
| يومي | مراجعة أخطاء API و1027/1102، فشل المزامنة | يوميًا |
| أسبوعي | بلاغات المحتوى، دروس بلا صوت، صور بلا alt | أسبوعيًا |
| شهري | تصدير D1 → R2، مراجعة حجم القاعدة (حد 500MB) | شهريًا |
| ربع سنوي | إعادة التحقق من حدود Cloudflare وأسعارها | ربع سنوي |
