# العمل دون اتصال والمزامنة

## 1. ما يعمل دون اتصال (بعد تنزيل مسبق) — وما لا يعمل

| يعمل ✅ | يحتاج اتصالًا ❌ |
| --- | --- |
| فتح التطبيق (shell) | إنشاء حساب/تسجيل دخول من جهاز جديد |
| الدروس المنزَّلة (نص + تمارين + تفسيرات) | مزامنة التقدم بين الأجهزة |
| الصوت المنزَّل | استعادة كلمة المرور |
| حل التمارين وحفظها في طابور | تنزيل محتوى جديد |
| مراجعة المفردات المحفوظة محليًا | إشعارات Push |
| عرض «تقدم محلي غير مُزامَن» بوضوح | التحقق من الإتقان النهائي/فتح مستوى جديد |

**لا ندّعي** عملًا كاملًا دون اتصال. لافتة دائمة تُظهر: «متصل / دون اتصال — 3 عمليات بانتظار المزامنة».

## 2. Service Worker

| نوع المورد | الاستراتيجية |
| --- | --- |
| `index.html`, JS/CSS المُبصَّم | `CacheFirst` + تحديث في الخلفية |
| حزمة درس | `StaleWhileRevalidate` + حدود 30 حزمة |
| صوت | `CacheFirst` بحد أقصى 40 MB (LRU) |
| صور | `CacheFirst` بحد 15 MB |
| `/api/content/*` | `NetworkFirst` مع `maxAge 24h` |
| `/api/auth/*`, `/api/learn/*`, `/api/review/*` | **بلا كاش** (`NetworkOnly`) — لا تُخزَّن استجابات مستخدم |
| صفحات قانونية | `StaleWhileRevalidate` |

إصدار الكاش: `CACHE_VERSION = build hash`. عند إصدار جديد: `skipWaiting` بعد موافقة المستخدم («تحديث متاح») لا تلقائيًا أثناء درس.

## 3. تخزين IndexedDB (قاعدة `esar`)

| Store | المفتاح | المحتوى | السقف |
| --- | --- | --- | --- |
| `lessons` | `${slug}@${versionId}` | حزمة درس منزَّلة | 30 حزمة |
| `vocab` | `normalized` | مدخل + جدولة | 2000 |
| `attempts` | `eventId` (ULID) | محاولة غير مُزامَنة | 5000، تُرفض الأقدم بتحذير |
| `reviews` | `itemType:itemId` | حالة SRS محلية | — |
| `meta` | `key` | آخر مزامنة، إصدار الكاش، وقت الخادم المرجعي | — |
| `downloads` | `bundleId` | فهرس التنزيلات وحجمها | — |

سجل المحاولة المحلي:
```json
{
  "eventId": "01J...ULID",
  "lessonId": "lsn_...",
  "lessonVersionId": "lv_...",
  "exerciseId": "ex_...",
  "answer": {"value": "café"},
  "durationMs": 4200,
  "occurredAt": "2026-10-21T09:12:03Z",
  "clientSeq": 17,
  "syncState": "pending"
}
```

## 4. المزامنة

```
1. عند online (أو كل 60s إن كان التطبيق مفتوحًا) → التحقق من الجلسة (GET /api/me)
2. إن 401 → إيقاف المزامنة، إظهار «سجّل الدخول للمزامنة» (المحاولات تبقى محفوظة)
3. إرسال دفعات ≤20 محاولة: POST /api/learn/attempts:batch
4. لكل محاولة: الخادم يتحقق من eventId (idempotent) → يطبّق → يعيد نتيجة معتمدة
5. العميل: يؤكد المحاولات المقبولة فقط (syncState='synced') ويحتفظ بالفاشلة مع سبب
6. تعارض الإصدار (409) → يُعلَّم السجل contentChanged، ويُعرض للمستخدم: «الدرس تغيّر، أعد فتحه» دون حذف المحاولة
7. تعارض الساعة: لا تُستخدم ساعة الجهاز لإثبات صحة النتيجة. الخادم يسجّل server_recorded_at ويستخدم occurred_at للمعلومات فقط
```

**منع التكرار:** `user_exercise_attempts.client_event_id UNIQUE` + `offline_sync_receipts.idempotency_key PK`. إعادة إرسال نفس الدفعة لا تمنح XP مرتين: `xp_ledger.idempotency_key = "lesson:" + lessonId + ":" + attemptBatchId`.

**لا تُمسح العمليات المحلية قبل تأكيد الخادم.** مسح الكاش لا يمسح `attempts`.

## 5. التنزيلات

- زر «تنزيل الوحدة» يعرض **الحجم التقديري** قبل البدء (نص + صوت).
- `offlinePriority` (0–2) يحدد ما يُنزَّل تلقائيًا: 2 = الدرس التالي فقط، لا أكثر.
- لا تنزيل تلقائي لكل المنهج أبدًا.
- إدارة التنزيلات: قائمة، حجم لكل عنصر، حذف فردي/جماعي، إجمالي.
- عند امتلاء التخزين (`QuotaExceededError`): رسالة واضحة + اقتراح حذف + لا فقدان محاولات.

## 6. حالات الاختبار الإلزامية (بند 35/21 من الموجز)

| # | السيناريو | المتوقع |
| --- | --- | --- |
| O1 | قطع الشبكة أثناء الدرس | يمكن الإكمال، تظهر لافتة، المحاولات في الطابور |
| O2 | إعادة تحميل الصفحة دون اتصال | يُستأنف الدرس من التخزين المحلي |
| O3 | إغلاق التطبيق وفتحه لاحقًا | المحاولات باقية |
| O4 | عودة الاتصال | مزامنة تلقائية + إشعار «تمّت مزامنة N» |
| O5 | إعادة إرسال نفس الدفعة يدويًا | 0 تكرار XP، 0 تكرار محاولات |
| O6 | تغيّر إصدار الدرس أثناء الانقطاع | 409 واضح + إعادة تحميل + حفظ السجل |
| O7 | امتلاء التخزين | رسالة + تنزيل لا يُفسد الحالة |
| O8 | جلسة منتهية | توقف المزامنة دون فقدان العمليات |
| O9 | تعديل ساعة الجهاز | لا أثر على XP أو الفتح |
| O10 | مستخدمان على نفس المتصفح | مساحة مفاتيح معزولة بـ`userId` وتُمسح عند الخروج |

## 7. حدود معلنة

- التخزين المحلي قد يُمسح من المتصفح عند نقص المساحة؛ لذلك المزامنة أولوية لا رفاهية.
- iOS Safari يقيّد التخزين الخلفي؛ التطبيق يطلب من المستخدم عدم إغلاق التبويب أثناء المزامنة الطويلة ويعرض الحالة.
- الإشعارات على iOS تتطلب تثبيت PWA على الشاشة الرئيسية — يُشرح في الإعدادات.
