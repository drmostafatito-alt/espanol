# المساهمة

## 1. دورة العمل لكل مهمة

```
1. افحص الحالة الحالية (git status, الاختبارات)
2. حدّد النطاق في سطر واحد
3. خطة مختصرة (≤5 أسطر) في وصف الـPR
4. أصغر تغيير مترابط
5. شغّل: check-sql + validate-content + test + typecheck
6. افحص بصريًا (هاتف + كمبيوتر + RTL)
7. حدّث الوثائق ذات الصلة + CHANGELOG
8. سجّل ما لم يكتمل بصراحة
```

## 2. قواعد الكود

| المجال | القاعدة |
| --- | --- |
| TypeScript | `strict: true`, لا `any` بلا تعليق سبب |
| الأسماء | `snake_case` في SQL، `camelCase` في TS، `kebab-case` في المسارات |
| CSS | CSS Modules + متغيرات `:root`؛ لا قيم لونية مباشرة في المكونات |
| RTL | لا `left/right`؛ استخدم `inline-start/end` |
| النصوص | لا نصوص عربية/إسبانية صريحة في المكونات → ملفات i18n |
| الاستعلامات | معاملات مربوطة فقط؛ لا تجميع سلاسل SQL |
| الأخطاء | لا `catch` صامت؛ لا ابتلاع أخطاء لتُظهر نجاحًا |
| الوقت | كل طوابع D1 UTC ISO-8601؛ تحويل المنطقة في العميل |
| المعرّفات | ULID نصي، لا `rowid` كهوية خارجية |

## 3. المحتوى

- أي ملف محتوى جديد يمر عبر `validate-content.mjs`.
- لا نشر بلا `content_review_records` بشريين (إسباني + عربي).
- لا تُضاف مفردة بلا مثال وترجمة وتلميح نطق.
- لا تُنسخ نصوص من معاجم محمية.

## 4. الالتزامات (Commits)

```
feat(learn): add word_order exercise validator
fix(auth): reject reused password reset token
content(a1): add cafe lesson draft
docs(security): document PBKDF2 calibration
test(srs): cover lapse interval handling
```
كل التزام يذكر **ما لم يُنجز** إن وُجد.

## 5. مراجعة الكود (Definition of Done)

- [ ] اختبارات جديدة أو تحديثها (لا ميزة بلا اختبار)
- [ ] `validate-content` و`check-sql` PASS
- [ ] لا أسرار ولا بيانات شخصية في السجلات
- [ ] إتاحة: تركيز/تسميات/تباين
- [ ] توثيق محدَّث (وإن كان سطرًا في CHANGELOG)
- [ ] لا ادعاء "مكتمل" بلا دليل

## 6. ما لا يُقبل

- تعطيل اختبار أو إخفاء فشله.
- إرجاع نجاح وهمي (200 مع رسالة "تم").
- إضافة مكتبة ثقيلة لوظيفة صغيرة.
- بيانات وهمية معروضة كأنها محفوظة.
- نسخ تصميم/أصول منتج آخر.
