# الأمن وحماية البيانات

## 1. نموذج التهديد (مختصر)

| التهديد | مثال | التخفيف |
| --- | --- | --- |
| سرقة اعتماد | تخمين كلمة مرور، تسريب قاعدة | PBKDF2 + pepper (فشل مغلق) + حدود معدل + رسائل لا تكشف التسجيل + جلسات معتمة + خمول 14 يومًا |
| سرقة جلسة | XSS، جهاز مشترك | كوكي HttpOnly/Secure/SameSite، تخزين hash فقط، إبطال الجلسات |
| تصعيد صلاحيات | تعديل الدور من الواجهة، طلب إداري | فحص الصلاحية على الخادم لكل مسار + `role_id` غير قابل للتعديل من العميل |
| IDOR | قراءة تقدم مستخدم آخر بـid | كل استعلام مقيّد بـ`user_id` من الجلسة لا من الطلب |
| تلاعب بالتقدم/XP | إرسال `xp: 9999` أو إعادة إرسال | الخادم يحسب XP؛ `idempotency_key` فريد؛ لا حقل XP في الطلبات |
| فتح دروس مقفلة | طلب درس لم يُفتح | فحص `unlock` على الخادم قبل إرجاع حزمة الدرس |
| حقن SQL | نص في حقل بحث | استعلامات مُعدّة (bindings) فقط؛ لا تجميع سلاسل |
| XSS | تفسير يحتوي HTML من مستخدم | لا `dangerouslySetInnerHTML` لمحتوى مستخدم؛ Markdown يُعالج بمُعقِّم allowlist |
| CSRF | نموذج خارجي يرسل طلبًا | SameSite=Lax + فحص Origin/Sec-Fetch-Site + إلزام Content-Type: JSON للكتابة (لا توكن مزدوج — لم يُنفَّذ) |
| CSRF/تكرار | ضغط متكرر على «تحقق» | مفاتيح idempotency + حد معدل لكل مستخدم |
| إغراق | آلاف الطلبات | حدود معدل في D1 على المسارات الحساسة |
| إساءة استخدام الاستعادة | تجربة بريدات | رد ثابت الزمن والنص دائمًا: «إذا كان البريد مسجلًا فسيصلك رابط» |
| رفع ملفات خطرة | صورة تحمل SVG بسكربت | قبول `webp/avif/png/jpg` فقط، فحص magic bytes، تخزين في R2، تقديم من نطاق منفصل، لا SVG مرفوع |

## 2. المصادقة

```
كلمة المرور: PBKDF2-HMAC-SHA256 فوق HMAC-SHA256(pepper, password)
            التخزين: pbkdf2-sha256$<iters>$<saltB64url>$<hashB64url>
            الصيغة القديمة pbkdf2$… تُقبل للقراءة فقط وتُرقّى تلقائيًا عند أول دخول ناجح
            الـpepper: سر ≥32 حرفًا؛ غيابه = 503 على مسارات المصادقة (فشل مغلق)
الجلسة:     توكن 32B عشوائي (base64url) → كوكي __Host-ses على HTTPS / ses محليًا
            HttpOnly; Secure; SameSite=Lax; Path=/; Priority=High
            في D1: sha256(token) فقط. مدة 30 يومًا + خمول 14 يومًا + سقف 10 جلسات
الخروج:     إبطال الصف في القاعدة + مسح الكوكي
التحقق من البريد: مشروط بإعداد مزود بريد؛ بدونه `email_verified_at = null` ولا يُدّعى غير ذلك.
```

**قياس R1 (حد CPU 10 ms) — قياس فعلي على workerd (لا تقدير):** `node tools/bench-kdf.mjs` → `reports/kdf-benchmark.md`.

| التكرارات | الوسيط | نسبة متطلب OWASP (600,000) | داخل 10ms؟ |
| --- | --- | --- | --- |
| 20,000 | 4 ms | 3.3% | نعم |
| **30,000 (المطبَّق)** | **5 ms** | **5.0%** | **نعم** |
| 50,000 | 9 ms | 8.3% | على الحد |
| 100,000 | 18 ms | 16.7% | لا |
| 210,000 | 38 ms | 35.0% | لا |
| 600,000 | 111 ms | 100% | لا |

**البدائل التي اختُبرت ورُفضت بالقياس:** PBKDF2-HMAC-SHA512 (4.8% مقابل 5.0% عند نفس الزمن — لا ميزة)، Argon2id (workerd يمنع ترجمة WASM وقت التشغيل، وحتى تقديريًا 24–60 ms = 2.4–6× الميزانية)، scrypt (غير قابل للتحميل + ذاكرة 64MB).

**القرار المطبَّق:** `PBKDF2_ITERATIONS = 30000` + pepper سري. الأثر: **5% من متطلب OWASP** — أضعف من المعيار، و**ليس** أمانًا مكافئًا. هذا **حدّ منصة مقيس**، وليس اختيارًا.
**التخفيف الحقيقي:** pepper (يحمي قاعدة مسروقة وحدها فقط)، حدود معدل، سياسة كلمات مرور 12+ مع قائمة شائعة، قفل حساب، سجل تدقيق.
**البوابة:** `ALLOW_PUBLIC_SIGNUP="false"` في الإنتاج حتى يُعتمد حل مطابق للمعيار. انظر `docs/21_SECURITY_REVIEW_PHASE1.md` §7 للخيارات الثلاثة والقرار المطلوب من المالك.
**عند الترقية:** رفع `PBKDF2_ITERATIONS` وحده كافٍ — إعادة التجزئة تحدث تلقائيًا عند أول دخول لكل مستخدم.

## 3. الحدود المعدّلة (Rate limits)

| المسار | الحد | المفتاح |
| --- | --- | --- |
| `POST /api/auth/login` | 10/دقيقة + 10/15دقيقة | IP-hash + بريد مُطبَّع |
| `POST /api/auth/signup` | 10/ساعة | IP-hash (مراعاة CGNAT) |
| قفل الحساب | 5 محاولات فاشلة ⇒ 15 دقيقة (ينتهي فعلًا بانقضائها) | معرّف المستخدم |
| `POST /api/lessons/:slug/answers` | 120/دقيقة | user |
| `POST /api/lessons/:slug/complete` | 60/دقيقة | user |
| `POST /api/me/placement` | 3/يوم | user |
| `POST /api/review/answers` | 120/دقيقة | user |

لا توجد حدود على مسارات غير المذكورة أعلاه. لا يوجد مسار `reset` أو `attempts:batch` أو `push/subscribe` — ما زالت غير منفَّذة، ولا يُدَّعى وجود حدود لها.

التخزين: `rate_limits(bucket, window_start, count)` بكتابة واحدة لكل نافذة قدر الإمكان (تقليل كتابات D1).

## 4. التحقق من المدخلات

- التحقق يدوي صارم على الخادم لكل مسار (لا مكتبة `zod` مستخدمة)؛ مخططات المحتوى في `content/schema` للاستيراد والمدقق.
- طول أقصى لكل حقل (مثلًا: اسم 80، ملاحظة بلاغ 500)، وحجم طلب أقصى 64 KB للـ JSON، 200 KB للدفعة.
- رفض الحقول غير المعروفة (لا «تمرير صامت»).
- تطبيع البريد (`lower/trim`) قبل التخزين والمقارنة.

## 5. الصلاحيات

- `requirePermission(ctx, 'content.publish')` كدالة بوابة على كل مسار إداري.
- الأدوار الستة وبذور صلاحياتها في `0002_seed_reference.sql`.
- لا يغيّر المستخدم دوره؛ تعديل `role_id` يحتاج `roles.manage` (super_admin).
- **إخفاء زر الإدارة ليس حماية**: كل مسار يُعاد فحصه في الخادم (اختبارات T6).

## 7. البيانات الشخصية

| البيانات | الاحتفاظ | ملاحظات |
| --- | --- | --- |
| البريد/الملف | حتى حذف الحساب | لا يُعرض في صفحات عامة |
| محاولات التمارين | 180 يومًا تفصيلًا ثم تجميع | `privacy.retention_attempts_days` |
| التسجيلات الصوتية | **محليًا في المتصفح فقط** | لا تُرفع افتراضيًا؛ إن أُضيف رفع مستقبلًا: موافقة صريحة + مدة محددة |
| IP | لا يُخزَّن صريحًا | يُخزَّن hash فقط للحدود الأمنية |
| بيانات إعلانية | لا شيء | لا مشاركة مع معلنين |

- تصدير البيانات: JSON يشمل الحساب + التقدم + المفردات + سجل المراجعة (بلا أسرار).
- حذف الحساب: طلب → تعطيل فوري (`pending_deletion`) → حذف فعلي بعد 30 يومًا (سياسة معلنة) → إبقاء سجلات تدقيق مجهولة الهوية.
- لا سجلات تحتوي كلمات مرور/توكنات/محتوى تسجيلات.

## 8. النسخ الاحتياطي والاستعادة

- D1 Time Travel (7 أيام Free) للطوارئ القريبة.
- تصدير أسبوعي للمحتوى (Git) وتصدير شهري لبيانات التقدم المجمّعة إلى R2 (بلا جداول جلسات).
- **اختبار استعادة** إلزامي في المرحلة 9: استعادة قاعدة staging من تصدير، وتشغيل اختبارات القراءة الأساسية.

## 9. الرؤوس الأمنية (تُطبَّق في Worker)

```
Content-Security-Policy: default-src 'self'; img-src 'self' data: https://media.example; media-src 'self' https://media.example;
  script-src 'self'; style-src 'self'; font-src 'self'; connect-src 'self'; frame-ancestors 'none'; base-uri 'none'; form-action 'self'
Strict-Transport-Security: max-age=31536000; includeSubDomains
X-Content-Type-Options: nosniff
Referrer-Policy: strict-origin-when-cross-origin
Permissions-Policy: microphone=(self), camera=(), geolocation=()
Cross-Origin-Opener-Policy: same-origin
```
الإعلانات (عند تفعيلها) تحتاج تمديد CSP بشكل مضبوط للمزوّد المعتمد فقط — لا `unsafe-inline`.
