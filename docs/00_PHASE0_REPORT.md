**التاريخ:** 2026-10-21 · **المنفِّذ:** فريق التطوير · **الحالة:** مكتمل ✅ (مع بنود معلَّقة تحتاج قرار المالك)

## 1. فحص البيئة (نتائج فعلية، لا مفترضة)

| الأمر | النتيجة الفعلية |
| --- | --- |
| `pwd && ls -la` | `/home/user` — **مجلد فارغ تمامًا**. لا يوجد مشروع قائم. |
| `node -v` / `npm -v` | `v20.20.2` / `10.8.2` |
| `python3 -V` | `3.13.16` |
| `git -v` | `2.47.3` |
| `which wrangler sqlite3 pnpm yarn bun` | **لا شيء منها مثبَّت** |
| `npm ls -g` | `corepack`, `ijavascript`, `npm` فقط |
| الشبكة (npm registry) | `HTTP 200` — تثبيت الحزم ممكن داخل الجلسة |
| الموارد | 2 vCPU · ~1.9 GB RAM · 21 GB مساحة حرة |

### استنتاجات الفحص
1. **المشروع جديد بالكامل** → لا يوجد ما يجب الحفاظ عليه (بند 10 من الموجز لا ينطبق عمليًا).
2. لا يوجد `wrangler` ولا حساب Cloudflare متصل → **لا يمكن نشر أي شيء**، ولا يمكن إنشاء قاعدة D1 حقيقية عن بُعد. النشر يتطلب تصريح المالك ومصادقة `wrangler login`.
3. `node_modules` **لا يُحفظ** في بيئة العمل (خارج لقطة المشروع) → كل الأدوات التي أكتبها في المرحلة صفر **بلا اعتماديات خارجية**، حتى تظل قابلة للتشغيل لاحقًا.
4. `sqlite3` غير مثبت. تحققتُ من DDL نصيًا عبر `tools/check-sql.mjs`؛ التشغيل الفعلي للـ migrations سيتم عبر `wrangler d1 migrations apply` على قاعدة تطوير عند توفر الحساب (خطوة بوابة في المرحلة الأولى).
5. لا يوجد متصفح آلي (Playwright) مثبت الآن → اختبارات E2E تُخطَّط في المرحلة الأولى مع تثبيت `@playwright/test` داخل المشروع (سيعمل، لكنه لن يُحفظ بين الجلسات — يُعاد تثبيته بأمر واحد موثق).

## 2. التحقق من حدود المنصة (حرج — لا يُبنى على أرقام محفوظة)

تحققتُ من التوثيق الرسمي اليوم 2026-10-21 (التفاصيل والأرقام في `docs/18_PLATFORM_LIMITS_VERIFIED.md`):

| الحد | القيمة على الخطة المجانية | الأثر المعماري المباشر |
| --- | --- | --- |
| Workers Requests | **100,000/يوم**؛ ملفات static assets مجانية وغير محدودة العدد | الواجهة تُقدَّم كملفات ثابتة؛ الـ Worker للـ API فقط |
| Workers CPU | **10 ms لكل طلب** | لا SSR لمشروع React كامل. تحقق كلمات المرور (PBKDF2) يحتاج قياسًا فعليًا — انظر المخاطرة R1 |
| D1 حجم القاعدة | **500 MB لكل قاعدة** (5 GB للحساب) | نصوص فقط في D1. الصوت والصور في R2. سياسة تقليم المحاولات القديمة إلزامية |
| D1 قراءات/كتابات | **5M صف/يوم** و **100,000 صف/يوم** — **تطبيق صارم منذ 2026-09-01** | كل محاولة تمرين = كتابات قليلة. لا كتابة صف لكل نقرة. تجميع (rollup) يومي |
| D1 استعلامات لكل استدعاء Worker | **50** | استخدام `batch()` وتقليل الرحلات (N+1 ممنوع) |
| R2 | 10 GB تخزين + 1M Class A + 10M Class B شهريًا، بلا رسوم خروج | الصوت (Opus ~12–20 KB/جملة) يُخدَّم من R2 عبر نطاق مخصص حتى **لا يستهلك حصة الـ Worker** |
| Workers حجم الحزمة | 64 MiB غير مضغوط، 25 MiB لكل ملف، 20,000 ملف لكل إصدار | لا تُحزَم مكتبة صوتية داخل الـ bundle إطلاقًا |

**الخلاصة:** الخطة مجانية **صالحة للمرحلة المبكرة فقط**، ولها سقوف صلبة. سأوثّق ذلك للمستخدم بصدق (بند 20/27 من الموجز) ولا أعد بمجانية غير محدودة.

## 3. الافتراضات (موثقة كي لا تُخلط بالحقائق)

| # | الافتراض | حدوده / ماذا لو خطأ |
| --- | --- | --- |
| A1 | المستخدم المستهدف مصري/عربي، يقرأ العربية بسهولة، وقد لا يعرف حروف الإسبانية | لو كان الجمهور أوسع (خليجي/مغاربي) نضيف حزمة تعليقات إقليمية؛ البنية تدعم ذلك بحقل `explanation_ar` + `note_ar_eg` |
| A2 | التعلّم والاستخدام الأول على الهاتف | التصميم mobile-first. لو كان الكمبيوتر أولًا يُعاد ترتيب أولويات الشاشات لا البنية |
| A3 | الحساب مجاني بالكامل عند الإطلاق، والإعلانات اختيارية لاحقًا | موثّق في `02_ARCHITECTURE.md` |
| A4 | لا يوجد مزود TTS مجاني مضمون وقت التشغيل | استراتيجية الصوت: ملفات مُولَّدة/مسجَّلة مسبقًا (build-time) + `speechSynthesis` كاحتياط صريح |
| A5 | بريد إلكتروني للمصادقة لكن بدون إرسال بريد إلزامي في النسخة الأولى | إعادة تعيين كلمة المرور تحتاج مزود بريد — **بوابة خارجية**، لا يُدّعى أنها تعمل قبل إعداده |
| A6 | D1 هي مصدر الحقيقة للتقدم | العميل يرسل "محاولات" فقط، والخادم يحسب XP/الفتح/الجدولة |
| A7 | لا ذكاء اصطناعي وقت التشغيل | كل التقييم بقواعد حتمية + مخازن محتوى |
| A8 | Cloudflare Pages/Workers وD1/R2 فقط | لا قاعدة بيانات خارجية مدفوعة |

## 4. المخاطر الكبرى وخطط التعامل

| # | المخاطرة | الاحتمال/الأثر | التخفيف |
| --- | --- | --- | --- |
| **R1** | تجزئة كلمة المرور (PBKDF2) تتجاوز **10 ms CPU** على الخطة المجانية | متوسط / حاسم للدخول | قياس فعلي في المرحلة 1. إن تجاوز: عدد تكرارات مُعاير (مثلًا 30k–60k) + pepper سري في متغير بيئي، مع توثيق المفاضلة. البديل المدفوع ($5) يُطرح كقرار للمالك، لا يُتخذ ضمنيًا |
| **R2** | 100,000 طلب/يوم تُستهلك بسرعة (كل `fetch` للـ API = 1 طلب) | عالٍ عند النمو | (أ) static assets للأصول، (ب) R2 عبر نطاق مخصص للصوت، (ج) كاش HTTP على القراءات العامة، (د) حزمة محتوى الدرس تُجلب مرة واحدة وتُخزَّن في IndexedDB |
| **R3** | 500 MB لكل قاعدة D1 مع نمو سجل المحاولات | متوسط | تقليم/تجميع المحاولات الأقدم من 180 يومًا إلى جداول `daily_activity` و`user_vocabulary_progress`، مع سكربت صيانة مجدول |
| **R4** | جودة الصوت: لا TTS مجاني مضمون | عالٍ / تعليمي | مسار مزدوج: أصول صوتية مُراجَعة في R2 (الأساس)، و`speechSynthesis` كاحتياط مع نص صريح عن محدوديته. لا ادعاء بجودة أصلية |
| **R5** | تقييم النطق آليًا بلا تكلفة | عالٍ | لا ادعاء بتقييم صوتي. التسجيل + استماع ذاتي + مقارنة بالنموذج + (اختياري) `SpeechRecognition` إن توفر، مع وسم النتيجة "مؤشر تقريبي" وعدم منع التقدم |
| **R6** | الالتزام بحدود تجارية عند إضافة إعلانات | متوسط | مواضع إعلان محددة مسبقًا، تُدار من الإعدادات، بلا حقن JS اعتباطي |
| **R7** | تضخّم عدّاد "5000 كلمة" بترجمات آلية | عالٍ / جودة | مدقق تكرار + قواعد جودة + بوابة مراجعة بشرية؛ العدّاد يُقاس بـ`content-metrics.mjs` لا يدويًا |
| **R8** | تعارض مزامنة العميل/الخادم | متوسط | مفاتيح idempotency + إصدار محتوى + تسوية بالخادم (انظر `09_OFFLINE_SYNC.md`) |
| **R9** | بلا مزود بريد = لا استعادة كلمة مرور حقيقية | متوسط | توثيق ذلك كـ"غير متاح حتى يتم إعداد مزود"؛ توفير مسار "رابط استعادة يُنشئه المشرف" كحل مؤقت آمن للمرحلة التجريبية |
| **R10** | إتاحة الوصول (WCAG 2.2 AA) مع واجهة ثنائية الاتجاه | متوسط | نظام تصميم يفرض تباينًا وحالات تركيز، وفحوص آلية + مراجعة يدوية في المرحلة 9 |

## 5. القرارات المعمارية (مع المفاضلة)

| القرار | البديل المرفوض | سبب الاختيار |
| --- | --- | --- |
| **SPA على React+TS+Vite تُخدَّم كأصول ثابتة من Worker**، والـ Worker للـ API فقط | SSR كامل داخل Worker | CPU 10 ms لا يحتمل SSR؛ static assets مجانية وغير محدودة. المفاضلة: SEO للصفحات العامة يُعالَج بمسار pre-render لصفحات محدودة لاحقًا |
| **جلسات معتمة (opaque) في D1 + كوكي HttpOnly** | JWT في localStorage | لا JS يقرأ التوكن، إبطال فوري ممكن، لا أسرار في الواجهة |
| **D1 نصوص فقط، والأصول في R2** | أصول ثنائية في D1 | حد 500 MB/قاعدة و2 MB/صف؛ R2 صالح للصوت بلا رسوم خروج |
| **محتوى كـJSON في المستودع → استيراد إلى D1 عبر سكربت** | تحرير مباشر في D1 من البداية | Git = مراجعة وتاريخ وإصدارات؛ D1 = مصدر التشغيل |
| **محرك تمارين قائم على تعريف نوع + تحقق مخطط** | منطق مخصص لكل تمرين | إضافة أنواع جديدة بدون مسّ المحرك |
| **مراجعة متباعدة SM-2 معدَّلة (بالخادم)** | جدولة عشوائية أو على العميل | قابلية الاختبار والتكرار |
| **بلا اعتماديات في أدوات مرحلة صفر** | ajv/zod الآن | `node_modules` غير محفوظ؛ الأدوات تعمل دائمًا |
| **مخططات JSON مكتوبة يدويًا + مدقق مخصص** | مكتبة مخططات | نفس السبب؛ لاحقًا يُنتقل إلى `zod` داخل التطبيق مع بقاء المدقق مرجعًا |

## 7. ما لم يُنفَّذ (ولن يُدّعى)

- ❌ لا كود تطبيق (React/Worker)، لا مصادقة، لا قاعدة بيانات منشورة.
- ❌ لا 5000 مدخل معجمي ولا 7000 كلمة تحريرية (النموذج العمودي فقط). هذه أهداف المراحل 2–3 وتُقاس بالأدوات.
- ❌ لا صوت ولا صور (لا أصول متاحة، ولا مزود TTS). الاستراتيجية موثقة فقط.
- ❌ لا لوحة إدارة، لا إشعارات، لا إعلانات.
- ❌ لا اختبارات E2E (لا يوجد تطبيق بعد). الموجود: مدقق محتوى + فحص DDL.
- ❌ لم يُنشأ ترخيص، لم يُحدَّد الاسم النهائي، لم تُعبَّأ بيانات التواصل.

## 8. أسئلة تحتاج قرار المالك (قبل المرحلة 1)

1. **الاسم النهائي والشعار**: هل نبدأ بالاسم المؤقت `Español بالعربي` مع نظام branding قابل للتغيير، أم تُرسل الاسم/الشعار الآن؟
2. **حساب Cloudflare**: هل يوجد حساب متاح للنشر؟ وهل يُصرَّح بالخطة المجانية فقط أم بالمدفوعة ($5/شهر) إن اصطدمت المصادقة بحد 10 ms؟
3. **مزود البريد** (لتفعيل البريد واستعادة كلمة المرور): لا يوجد في الموجز مزود مجاني محدد. بدون قرار، ستكون استعادة كلمة المرور "غير مفعّلة" وموثقة كذلك.
4. **الصوت**: هل يوجد مصدر أصول صوتية (تسجيلات بشرية/مولّد TTS محلي) أم نعتمد `speechSynthesis` مؤقتًا؟
5. **مسار الكول سنتر**: هل الجمهور متمركز في مصر (لهجة/سوق مصري) أم عام؟ يحدد أمثلة السيناريوهات.
6. **المرحلة التالية**: تصريح بالانتقال إلى المرحلة 1 (أساس التطبيق: مصادقة + D1 + نظام إعدادات + إعداد المشروع)؟
