## 1) نتائج فورية من هذه الجولة (قبل أي محتوى جديد)

### 1.1 اختبارات المتصفح — حُلَّت

**كيف؟** كانت المكتبات الناقصة تُثبَّت بـ`apt` ويتطلب ذلك صلاحية؛ في هذه البيئة `sudo apt-get` يعمل. الخطوات الدقيقة:

```bash
sudo apt-get install -y --no-install-recommends \
  libnss3 libnspr4 libatk1.0-0 libatk-bridge2.0-0 libatspi2.0-0 \
  libxdamage1 libxkbcommon0 libasound2t64 libcups2 libxcomposite1 \
  libxrandr2 libgbm1 libpango-1.0-0 libcairo2 libgtk-3-0t64
./node_modules/.bin/playwright install chromium firefox
./node_modules/.bin/playwright test
```

ملاحظات تقنية مهمة:

- **Chromium** (101 MB، headless shell) يعمل.
- **Firefox** (Gecko) يعمل أيضًا — أي أننا نختبر محرّكَي عرض مختلفين فعليًا، لا نسختين من نفسه.
- **WebKit (Safari) غير ممكن هنا، والسبب فني دقيق:** أبنيته المتاحة لـUbuntu 20.04 تطلب sonames قديمة غير موجودة في Debian 13 (`libicu66`, `libwebp.so.6`, `libjpeg.so.8`, `libffi.so.7`). أضفت مشروع `iphone-safari` في `playwright.config.ts` **معطَّلًا** ويُفعَّل بـ`E2E_WEBKIT=1` على نظام مدعوم. **لا يجوز الادّعاء باختبار Safari حتى يُشغَّل فعليًا.**

### 1.2 نتيجة التشغيل الحقيقية

```
45 passed (1.2m)
```

5 بيئات × 9 اختبارات: `chromium-320` (لمس، 320px) · `chromium-desktop` · `android-chrome` (Pixel 7) · `firefox-desktop` · `firefox-320`.

### 1.3 ثلاثة أعطال حقيقية كشفها المتصفح (وأُصلحت)

| # | العطل | كيف ظهر | الإصلاح |
| --- | --- | --- | --- |
| 1 | **تمرير أفقي 88px على شاشة 320px** | `scrollWidth = 408` مقابل `clientWidth = 320` في الشاشة الرئيسية قبل الدخول | الشريط العلوي كان `flex` بلا التفاف فتخرج أزراره خارج الشاشة ⇒ `flex-wrap: wrap`؛ و`skip-link` كان مُخزّى بـ`inset-inline-start:-9999px` الذي يصبح `right:-9999px` في RTL فيمدّ الصفحة أفقيًا ⇒ الإخفاء بإزاحة رأسية |
| 2 | **زر «تحقّق» يبقى معطّلًا في تمرين إعادة الترتيب** | المتصفح: `locator.click` ينتظر 45 ثانية على زر `disabled` | الواجهة كانت تحفظ الإجابة نصًّا مدموجًا بينما الشرط يتوقع مصفوفة ⇒ تُحفظ الآن مصفوفة مرتّبة، والخادم يقبل الشكلين |
| 3 | **لا رسالة عند غياب صوت إسباني** | اختبار «لا صوت إسباني ⇒ رسالة عربية واضحة» فشل: لا شيء يظهر | كان `audio.play()` يُستدعى ونتيجته **تُهمَل**؛ الآن تُعرض رسالة عربية + زر «أكمل بدون صوت»، بلا أخطاء تقنية |

العطل الثالث كان يخالف بندًا صريحًا في مواصفة الصوت: «إذا لم يوجد صوت إسباني، اعرض رسالة واضحة + إعادة محاولة». لم يكن منفَّذًا، واختبار المتصفح هو ما أظهره.

### 1.4 إصلاحان مساعدان

- **`speechEs`**: النص الاحتياطي للنطق كان يُستنتج من «أول خيار»، وقد يكون مشتِّتًا فيُنطق نص خاطئ. الآن يُستخرج في الخادم من **نص الإجابة الصحيحة**، ويمكن للمحتوى تحديده صراحةً (أُضيف للحقل المسموح في مخطط التمرين).
- **حد التسجيل قابل للضبط محليًا**: `SIGNUP_RATE_LIMIT_PER_HOUR` (الافتراضي 10، وفي `.dev.vars` فقط 500 لاختبارات المتصفح). **لا يُضبط في الإنتاج**، والمنطق نفسه لم يُضعَّف: القيمة الافتراضية بقيت 10.

### 2.3 قواعد صادقة مقترحة (تحتاج موافقتك)

1. **لا ندّعي تغطية مستوى كاملًا.** الدرس المصغّر 7–12 دقيقة؛ 40 درسًا ≈ 7 ساعات درس. مستوى A1 في CEFR يقدَّر بـ80–100 ساعة تعلّم موجّه. لذلك: «يغطي أهدافًا تواصلية مختارة»، والمرجع موجود في الخريطة (`cefrReferenceHours`) للمقارنة لا للوعد.
2. **الترتيب الألفي ليس «الأكثر شيوعًا» بعد.** الترتيب الحالي داخلي (`internalRank`). عرضه للمستخدم بوصفه «أهم 1000 كلمة في الإسبانية» يتطلب **قائمة تكرار مرخَّصة وموثّقة** (قرارك: اعتماد مصدر، أو البقاء على ترتيب داخلي مع تسمية صادقة).
3. **المسار الجانبي لا يمنح XP مضاعفًا** لنفس الدرس.

## 3) نظام المراجعة المتباعدة — الأولوية 2

### 3.1 قرار المجدول (يحتاج موافقتك)

| الخيار | الحجة | العيب |
| --- | --- | --- |
| **SM-2 مبسّط (مقترح للنسخة 1)** | حتمي، سهل التحقق باختبارات، كافٍ لجودة أولية | أقل كفاءة من FSRS في تثبيت الذاكرة (مراجعات أكثر بنفس النتيجة) |
| FSRS-5 | أفضل منحنى تعلّم/مراجعة بفارق ملموس | يحتاج بيانات مراجعة حقيقية للمعايرة؛ بلا بيانات نستخدم معاملات افتراضية بلا دليل |

**التوصية:** SM-2 الآن + `scheduler_version` في كل صف. عند توفّر بيانات مراجعة حقيقية (آلاف المراجعات) نُجري مقارنة FSRS في وضع الظل ثم نتحول. **لا نقدّم FSRS بوصفه أدقّ بلا دليل من مستخدمينا.**

### 3.2 الجداول (D1) — مقترح

```sql
-- بطاقة واحدة لكل (مستخدم، مدخل، نوع الاسترجاع)
CREATE TABLE srs_cards (
  id                  TEXT PRIMARY KEY,
  user_id             TEXT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  vocabulary_entry_id TEXT NOT NULL REFERENCES vocabulary_entries(id),
  kind                TEXT NOT NULL DEFAULT 'recognition', -- recognition | production | listening
  state               TEXT NOT NULL DEFAULT 'new',         -- new | learning | review | relearning | suspended
  due_at              TEXT NOT NULL,
  interval_days       REAL NOT NULL DEFAULT 0,
  ease                REAL NOT NULL DEFAULT 2.5,
  reps                INTEGER NOT NULL DEFAULT 0,
  lapses              INTEGER NOT NULL DEFAULT 0,
  scheduler_version   INTEGER NOT NULL DEFAULT 1,
  last_review_at      TEXT,
  created_at          TEXT NOT NULL,
  UNIQUE (user_id, vocabulary_entry_id, kind)
);
CREATE INDEX idx_srs_due ON srs_cards (user_id, state, due_at);

-- سجل المراجعات: أثر كامل + منع التكرار
CREATE TABLE srs_reviews (
  id                  TEXT PRIMARY KEY,
  client_event_id     TEXT NOT NULL,
  user_id             TEXT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  card_id             TEXT NOT NULL REFERENCES srs_cards(id) ON DELETE CASCADE,
  rating              INTEGER NOT NULL CHECK (rating BETWEEN 1 AND 4), -- again|hard|good|easy
  prev_state TEXT, prev_interval_days REAL, prev_ease REAL, prev_due_at TEXT,
  next_state TEXT NOT NULL, next_interval_days REAL NOT NULL, next_ease REAL NOT NULL, next_due_at TEXT NOT NULL,
  response_ms         INTEGER,
  scheduler_version   INTEGER NOT NULL,
  reviewed_at         TEXT NOT NULL,
  UNIQUE (user_id, client_event_id)
);
```

### 3.3 القواعد غير القابلة للتفاوض

1. **الخادم وحده يحسب الموعد القادم.** العميل يرسل `{cardId, rating, clientEventId, responseMs}` فقط؛ أي `interval` أو `dueAt` من العميل يُهمَل تمامًا (نفس مبدأ XP في المرحلة 2).
2. **منع التكرار بنفس نمط المرحلة 2:** `UNIQUE(user_id, client_event_id)` ⇒ إعادة الإرسال تُعيد النتيجة المخزَّنة بلا مراجعة ثانية ولا تغيير في الموعد.
3. **سقف يومي:** 10 بطاقات جديدة + 100 مراجعة (قابل للضبط لكل مستخدم). لا «دين مراجعات» يتراكم ويحبس المتعلم.
4. **Leech:** 8 إخفاقات ⇒ `state='suspended'` مع عرض الكلمة في سياق جديد بدل تكرارها بلا نهاية.
5. **المراجعة تُغذّي الدقة:** تسجيل كل مراجعة يعني أن لوحة التقدم يمكنها قول «كلمات ثابتة» بصدق (`words_stable`) لا تخمينًا.
6. **توليد البطاقات من الدروس:** إتمام درس ⇒ إدخال `newVocabulary` كبطاقات `new` مستحقة الآن. مسار top1000 يولّد بطاقاته بنفس الآلية، بلا درس.

### 3.4 الواجهة (خلف موافقة)

شاشة مراجعة واحدة: بطاقة → تذكّر → إظهار → أربعة أزرار تقييم → البطاقة التالية. تعمل في 320px، بلا مؤقتات تُربك، مع إمكانية الخروج و resume على الخادم.

## 4) تحسين الاستيراد والتحقق — الأولوية 3

### 4.1 نُفِّذ الآن

- **`--dir <path>`** في `import-content.mjs` و`validate-content.mjs`: فحص مسودات جديدة بلا لمس مجلد العينات.
- **`speechEs`** في مخطط التمرين (نص النطق الاحتياطي) — يُستمد من الإجابة الصحيحة في الخادم.
- **الدرس الجديد يمرّ بالماسح**: `PASS` بصفر أخطاء، و3 تنبيهات مقصودة (انظر 4.4).
- **بناء خطة الاستيراد** للدرس الجديد: 96 أمرًا (`lessons=1 exercises=11 options=20 items=3 vocab=7`) — dry-run فقط، لم يُكتب شيء.

### 4.2 مخطط له (بعد الموافقة)

| التحسين | الفائدة |
| --- | --- |
| فحص اتساق `correctOptionIds` مع معرّفات الخيارات داخل نفس التمرين | **كان عطلًا صامتًا في المرحلة 2**: كل إجابات الاختيار كانت تُصحَّح خطأً |
| لزوم `distractorRationaleAr` لكل مشتِّت + `errorFeedback` لكل خيار | يمنع مشتِّتات عشوائية بلا سبب تربوي |
| لزوم `explanationAr` ≥ 20 حرفًا + فحص وجود العربية | يمنع تفسيرات شكلية |
| فحص أن الجملة الإسبانية لا تتجاوز مستوى الدرس (طول + مفردات غير مشروحة) | يمنع «A1» بلغة B2 |
| فحص الصوت: كل `audioKey` بصيغة `pending/` أو `audio/<sha>.opus` مسجَّل | يمنع مفاتيح وهمية |
| كشف المحتوى المكرر بين الدروس (تشابه > 90%) | يمنع نسخ الدروس لتضخيم الأعداد |
| `review_state` إجباري: `unreviewed → in_review → reviewed` مع هوية المراجع وتاريخه | لا نشر بلا مراجعة بشرية موثّقة |
| تقرير أثر الاستيراد (`--report json`) | يوضح ما سيتغيّر قبل الكتابة |

### 4.3 بوابة النشر (مقترح أن تكون صارمة)

الاستيراد يرفض رفع الحالة إلى `published` إذا لم يوجد: `reviewed_by` + `reviewed_at` + `spanishReviewer` + `translationReviewer` + اجتياز كل الفحوص بلا تحذيرات. **حتى الآن لا سبيل لنشر أي درس في هذا المستودع غير هذا المسار.**

### 4.4 التنبيهات الثلاثة على الدرس الجديد (مقصودة وشفافة)

1. مفردة `hola` غير موجودة في حزمة مفردات هذه الوحدة (موجودة في `a1-core-20`) — مسموح في `draft` فقط.
2. مفردة `me llamo` كذلك.
3. في مدخل `de`: المثال لا يحتوي المدخل حرفيًا (المثال «¿De dónde eres?» يحتوي «De» بحرف كبير).

هذه تنبيهات تُصبح **أخطاء** لحظة تحويل الدرس إلى `published` — أي أنها حاجز حقيقي، لا تحذير شكلي.

## 9) القيود التي تبقى سارية (تأكيد صريح)

- التطوير **محلي فقط**؛ لا نشر ولا `wrangler deploy`.
- **لا تغيير** في خطة Cloudflare أو حدودها أو اشتراكها.
- **لا فتح تسجيل عام** في الإنتاج (`ALLOW_PUBLIC_SIGNUP` يبقى قرارًا منفصلًا).
- **لا أسرار حقيقية**: `.dev.vars` سر تطوير فقط، و`PASSWORD_PEPPER` إنتاجي لم يُنشأ.
- **لا بيانات إنتاج** في الاختبارات: الحسابات تُنشأ لحظيًا ببريد `@example.com`.
- **كل محتوى جديد مسودة** حتى مراجعة بشرية موثّقة.
- **لا صوت** قبل اعتماد المصدر والترخيص والجودة.
- لا ادعاء تحقق على جهاز لم يُختبر (iOS/Safari مازال غير متحقَّق).

## 10) ما أنتظره منك الآن

1. موافقة أو تعديل على **هيكل المنهج** (`curriculum-map.v1.json`).
2. مراجعة **الدرس الواحد** في `docs/24_SAMPLE_LESSON_A1.md` — خصوصًا: هل مستوى الصعوبة مناسب لـA1؟ هل الشرح العربي واضح وغير مُترجم آليًا؟ هل التمارين متنوعة بما يكفي؟
3. اختيار قرارات القسم 8 (خصوصًا 1 و2 و3).

بعد ذلك أبدأ بالبند 1 و2 من خطة التنفيذ (الهيكل + SRS)، ثم أول وحدة A1 كاملة.
