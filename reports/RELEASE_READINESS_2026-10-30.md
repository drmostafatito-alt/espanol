## 3) المانع الثاني: PBKDF2 أقل من متطلب OWASP

### الأرقام (من مصدرها، لا من تقدير)
| المصدر | الرقم |
| --- | --- |
| OWASP Password Storage Cheat Sheet | PBKDF2-HMAC-SHA256 = **600,000** تكرار · Argon2id m≥19MiB t=2 p=1 · scrypt 2^17/8/1 |
| Cloudflare Workers Free | **10ms CPU/طلب** · 100k طلب/يوم · 128MB |
| Cloudflare Workers Paid | **5$/شهر** كحد أدنى · CPU افتراضي 30s · 10M طلب + 30M CPU-ms |
| قياسنا على workerd (وسيط 5 جولات) | 10k=2ms · 20k=3ms · **30k=5ms** · 50k=8ms · 100k=16ms · **600k=94ms** |
| Argon2id / scrypt | مستحيلان: `Wasm code generation disallowed by embedder` |

⇒ 30,000 = **5.0%** من المتطلب. 600,000 = **94ms**، أي 9.4× ميزانية الخطة المجانية (10ms) ⇒ **لا يمكن رفعه على الخطة المجانية؛ الرفع الأعمى يعطّل الدخول لا يقوّيه**.

### أثر التغيير على المستخدمين الحاليين (فحص كود فعلي)
- التحقق يقرأ عدد التكرارات **من الصف المخزَّن** (`src/worker/lib/password.ts`)، لا من متغيّر البيئة.
- `needsRehash()` يرقّي التجزئة تلقائيًا عند أول دخول ناجح.
⇒ **تغيير `PBKDF2_ITERATIONS` لا يكسر أي حساب قائم**، ولا يستطيع تخفيض قوة حساب قديم. القيمة الحالية 30,000 تبقى صالحة للقراءة إلى الأبد.

### الحل المطبَّق (بلا دفع وبلا كسر)
1. حسابات جديدة بكلمة مرور: **مغلقة** في الإنتاج.
2. حسابات جديدة عبر **Google OAuth** (authorization code + PKCE، تحقق RS256 من JWKS، `nonce`، `email_verified`، `state` بمقارنة زمنية ثابتة) — بلا كلمة مرور محلية أصلًا.
3. الحسابات القائمة: تبقى تعمل على 30k، وتُرقّى تلقائيًا كلما تغيّر الاحتياط مستقبلًا.

**يحتاج اشتراكًا مدفوعًا؟** لفتح التسجيل بالبريد: نعم، 5$/شهر (Owner رفضها 2026-10-28 نصًّا: «مش عاوز اي حاجه بفلوس»).
**يحتاج قرارًا؟** تأكيد التنازل المحدود، أو ترقية الخطة.

## 9) قائمة النشر (تنفيذها يحتاج تصريح المالك فقط)

```bash
# 0) نسخة احتياطية من قاعدة الإنتاج — قبل أي شيء
npx wrangler d1 export es-ar-prod --remote --config wrangler.production.toml --output backup-$(date +%F).sql

npx wrangler secret put PASSWORD_PEPPER --config wrangler.production.toml        # ≥32 محرفًا عشوائيًا

npm run build && node tools/check-deploy-ready.mjs --file wrangler.production.toml

# 5) النشر
npx wrangler deploy --config wrangler.production.toml
```

## 10) خطة التراجع

1. **تراجع الكود**: `npx wrangler rollback --config wrangler.production.toml` (يعيد الإصدار السابق خلال ثوانٍ).
2. **تراجع القاعدة**: استعادة `backup-YYYY-MM-DD.sql` عبر `wrangler d1 execute --remote --file`؛ ولا عكس SQL لأن كل المهاجرات إضافية.
3. **تراجع الإعداد**: إعادة `ALLOW_PUBLIC_SIGNUP` إلى `"false"` وإعادة النشر — لا يمس بيانات.
4. **إغلاق طارئ**: تعيين `ALLOW_PUBLIC_SIGNUP="false"` + إبطال الجلسات (`UPDATE sessions SET revoked_at=…`) بلا حذف أي حساب.
